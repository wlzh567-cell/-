이 프로젝트 폴더에 입주청소를 주력으로 하는 청소업체 랜딩페이지를 제작해줘.

먼저 현재 작업 폴더와 기존 파일 구조를 확인하고, 아래 파일을 처음부터 끝까지 모두 읽어줘.
- AGENTS.md
- docs/PRD.md
- CODEX_START.txt

읽은 파일의 실제 경로와 현재 앱 코드 유무를 짧게 알려준 다음, 바로 PRD의 Phase A를 구현해줘. 계획만 작성하고 끝내지 말고 실제 코드 작성, 실행, 검증까지 진행해줘.

앱 코드가 없다면 Next.js App Router + TypeScript + Tailwind CSS 기준으로 프로젝트를 초기화해줘. 이미 코드가 있다면 기존 구조, 패키지 매니저, 사용자 변경 사항을 보존하면서 구현해줘. 관련 없는 파일을 삭제하거나 되돌리지 마.

핵심 산출물은 랜딩페이지 1장이야.
- 입주청소를 전체의 60~70% 비중으로 가장 강하게 보여줘.
- 이사청소, 사무실 청소, 소파 청소, 의자 청소는 보조 서비스로 구성해줘.
- 주요 CTA 문구는 `견적 받기`로 통일하고 페이지 안의 문의 폼으로 이동하게 해줘.
- 토스·애플 계열의 넓은 여백, 큰 한국어 타이포, 명확한 위계, 결과 이미지 중심의 감성을 참고하되 특정 사이트를 복제하지 마.
- 밝고 정돈된 뉴트럴 배경, 진한 잉크색 글자, 하나의 청결감 있는 포인트 색, 비대칭 레이아웃과 절제된 모션을 사용해줘.
- 흔한 카드 반복, 보라색 AI 그라데이션, 로봇·반짝이 클리셰, 과한 유리 효과는 피해줘.

히어로와 결과 중심 비주얼부터 디자인 완성도를 잡은 다음, 입주청소 핵심 가치, 공간별 상담 범위, 보조 서비스, 상담 흐름, 견적 문의 폼, FAQ, 푸터 순서로 완성해줘.

실제 고객, 고객 로고, 후기, 별점, 가격, 할인, 연락처, 서비스 지역, 작업 건수, 경력, 만족도, 인증, 사업자 정보는 절대 임의로 만들지 마. 실제 작업 사진이 없으면 가짜 Before/After나 현장 사례를 만들지 말고, 일반·생성·대체 비주얼은 실제 사례가 아니라는 표시를 명확히 해줘.

회사명은 아직 미정이므로 가짜 상호를 만들지 마. 임시 워드마크는 `입주청소 전문`을 사용하고, 나중에 설정 한 곳에서 쉽게 바꿀 수 있게 해줘.

사업 정보가 필요한 미정 사항은 `docs/decisions.md`를 만들어 체크리스트로 기록해줘. 미정 정보 없이 진행 가능한 Phase A 작업은 질문 때문에 멈추지 말고 계속 진행해줘.

문의 폼은 PRD의 필드와 검증 규칙을 따르되 브라우저 로컬 검증만 구현해줘.
- 실제 API 호출, Server Action, DB 저장, 이메일·문자·카카오톡 전송, localStorage/sessionStorage 저장을 하지 마.
- 유효성 검증 성공 후 `입력 형식이 확인되었습니다. 현재는 데모 단계로 실제 견적 요청이 접수되거나 저장되지 않습니다.`라고 명확히 보여줘.
- 가짜 접수번호, 예약 완료, 상담 접수 완료 화면은 만들지 마.
- 폼 오류 접근성, 키보드 탐색, 보이는 포커스를 챙겨줘.

회원가입, 관리자, 결제, 실제 예약, 실제 AI 기능, 분석 SDK는 추가하지 마. 별도 승인이 필요한 Phase B/C 기능도 구현하지 마.

모바일을 우선하되 360, 390, 768, 1024, 1440px 전후를 확인해줘. 시맨틱 HTML, 색상 대비, 이미지 alt, reduced-motion, 레이아웃 이동 방지를 반영해줘. 외부 이미지를 사용한다면 사용 권한과 출처를 확인하고 docs/decisions.md에 기록해줘. 확인할 수 없다면 프로젝트 내부의 정직한 대체 비주얼을 사용해줘.

구현 후 가능한 범위에서 다음을 실행하고 오류를 고쳐줘.
- 프로덕션 빌드
- TypeScript 검사
- 린트
- 폼 핵심 검증 테스트
- 데스크톱과 모바일 브라우저 확인
- 키보드 탐색과 reduced-motion 확인
- 콘솔 오류와 깨진 링크 확인
